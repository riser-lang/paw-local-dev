$$\text{安装即用} \longrightarrow \text{首次引导(选目录+填Key/选离线)} \longrightarrow \text{首次平滑扫描(非阻塞+ETA)} \longrightarrow \text{智能批量审核(一键确认)} \longrightarrow \text{日常无感巡航守护}$$

| 验证维度 | 核心组件 | 真实性验证表现与代码落地点 | 验收判定 |
|---|---|---|---|
| **常驻进程** | `backend/main.py`<br/>`run.py` | FastAPI 搭配 Uvicorn 异步事件循环在后台持续常驻，绑定 `127.0.0.1:8800`。集成 Windows Mutex 单实例互斥机制（`PAW_Personal_Work_OS_SingleInstance_Mutex_v2`），并在端口冲突时自动顺延至 `8801+`，杜绝服务崩溃。 | **PASS** |
| **真实调度** | `backend/runtime_core/scheduler.py` | 独立后台守护线程 `SchedulerThread` 真实运行，支持 `realtime`（文件变更防抖触发）、`hourly`（定时轮询）与 `daily`。维护真实巡航计数（`total_cruises`）与任务心跳。 | **PASS** |
| **事件总线** | `backend/runtime_core/event_bus.py` | 采用内存级发布-订阅模式，维护真实事件环形队列（Ring Buffer），实时分发 `FILE_CHANGED`、`CRUISE_STARTED`、`KNOWLEDGE_PROPOSED`、`BACKUP_COMPLETED` 等系统核心事件，支持事件溯源审计。 | **PASS** |

## 3. Harness 架构现状与未来演进路线

针对评审关切的 Harness 测试与评估脚手架，PAW 团队给出了清晰严谨的架构定位：

```
                ┌──────────────────────────────────────────────┐
                │          PAW 业务层与工作台契约               │
                └──────────────────────┬───────────────────────┘
                                       │
                         调用 Harness 标准接口定义
                                       │
                                       ▼
                     ┌───────────────────────────────────┐
                     │   backend/runtime_core/           │
                     │   harness_adapter.py              │
                     │   (统一门面 HarnessAdapter)        │
                     └─────────┬───────────────┬─────────┘
                               │               │
        当前运行模式 (生产稳健)  │               │ 未来升级替换 (无缝插拔)
                               ▼               ▼
                     ┌────────────────┐ ┌────────────────────────┐
                     │ 本地确定性      │ │ 完整 OpenAI Harness     │
                     │ 评测与断言适配器│ │ (Official Test Driver) │
                     └────────────────┘ └────────────────────────┘
```

1. **是否真正接入官方 OpenAI Harness**：
   - 现网桌面版**未直接外挂臃肿且依赖繁重的官方 Python Harness 库**。原因在于官方 Harness 依赖特定联网验证机制与沉重的云端评测依赖，会导致桌面安装包膨胀数百兆并破坏离线可用性；
2. **当前 HarnessAdapter 的核心作用**：
   - 实现了工业标准的适配器门面（Facade Adapter），抽象出评测用例输入构造、预期契约校验、输出幻觉审计、因果断言与评分归一化逻辑；
   - 本次 A25 的 30 题问答基准评测正是通过该 Adapter 实施确定性注入与打分；
3. **是否支持未来替换与平滑升级**：
   - **完全支持**。业务层与 AI 助手层仅依赖 `HarnessAdapter` 暴露的接口标准，未来若需接入官方 OpenAI Harness 或自动化评测容器，仅需替换底层 Driver 实现，前端与 41 表底座 100% 零修改。

## 4. Universal Provider 接入与企业级安全

### 4.1 通用 OpenAI 兼容协议客户端
全面收敛模型交互，构建统一的 `UniversalOpenAIProvider`（位于 `backend/provider/adapter.py`）：
- 统一路由至标准 `/chat/completions` REST 规范；
- 预置 **DeepSeek**（`https://api.deepseek.com`）、**通义千问 Qwen**（`https://dashscope.aliyuncs.com/compatible-mode/v1`）、**OpenAI**（`https://api.openai.com/v1`）及**自定义兼容网关**四大预设模板；
- 彻底摒弃多个不同厂商 SDK 混合导致的依赖冲突与莫名回退问题。

### 4.2 连通性测试 5 分类人话排查指引（接口 `POST /v1/local/provider/test_connection`）
拒绝输出任何原始异常堆栈（如 `Traceback...`），统一输出精准的人话诊断指南：
- `AUTH_ERROR`：“API Key 填写有误，或该密钥对应的账户已欠费、被封禁或无权限。请登录模型官网核对密钥。”
- `URL_ERROR`：“Base URL 地址无效（服务端返回 404）。请检查地址拼写，并确认是否漏掉了路径后缀（例如缺少 /v1）。”
- `MODEL_ERROR`：“模型名称在当前提供商不存在或不可用，请核对模型名称是否拼写准确。”
- `NETWORK_ERROR`：“网络连接失败，无法连接到指定的服务器地址。请检查本地网络、代理设置或 Base URL 是否可以解析。”
- `TIMEOUT` / `RATE_LIMIT`：“请求响应超时或触发并发/速率限流，请稍后重试或检查配额。”

### 4.3 Windows 原生 DPAPI 密码学强加密
- 采用 Windows 原生操作系统级 `CryptProtectData` 与 `CryptUnprotectData` API 对用户填写的 API Key 进行本地硬件/用户绑定加密；
- 配置文件 `settings.json` 磁盘落盘仅为 Base64 密文；
- 控制中心回显一律打码掩码（如 `sk-09...f89a`）；
- 全局日志审计拦截器（`mask_secret`）强制生效，任何日志输出绝无明文泄漏。

## 5. 前端一致性与非阻塞交互体验

### 5.1 云端 PAW 前端信息架构 100% 映射保真
本地桌面版完整承载 React 18 高保真构建包，严格复刻云端 PAW 的五大核心业务视图：

```
PAW 工作台 (/app)
├── 今日看板 (/today)       -> 呈现工作简报、今日关注、动态提醒与每日指标
├── 项目中心 (/projects)    -> 展现活跃项目脉络、阶段里程碑、责任人与投入度
├── 知识资产库 (/knowledge)  -> 沉淀六大分类知识卡片、SOP、决策依据与证据引用
├── 待办工作流 (/todos)      -> 管理从工作成果自动提炼的行动事项与执行状态
└── 审核中心 (/review)      -> Human-Governed 人机协同中枢，候选审批与提交底座
```

### 5.2 工业级扫描与审核交互
1. **预扫描耗时预估（Pre-Scan）**：秒级递归统计符合条件的文件数，智能折算首次解析耗时并提供明确交互提示；
2. **平滑进度与实时动态**：总文件数、已处理数、当前解析文件名（高亮轮播）、已用时与剩余时间平滑估算；
3. **True Pause 系统资源释放**：暂停时立即调用 `gc.collect()` 释放解析临时占用内存，并通过 Win32 API 动态压低工作线程优先级，确保用户并行运行 Office 时丝滑顺畅；
4. **断点续扫（Checkpoint Resume）**：持久化状态记录于 `data/scan_checkpoint.json`，随时关闭软件或电脑，下次重启无缝接续，不重复处理已解析文档；
5. **非阻塞失败清单（Failed Catalog）**：针对损坏、受密码保护、被独占的文件，绝不弹窗打断，自动归入失败清单，给出人话原因并提供重试入口；
6. **智能批量审核**：候选条目自动按照「项目 / 主题 / 置信度」智能归组折叠，支持一键「勾选高置信度」，批量确认后严格由 Committer 生成单条审计流水写入正式表。

## 6. Evolution Engine 深度验收与成熟度评分

PAW 的核心灵魂在于其自我演进能力（Self-Evolving System）。经严格排查，演进引擎完全扎根于业务真实数据，绝非静态 Mock 接口：

### 6.1 核心演进维度验证明细

```
                    工作输入 (Word / Excel / PPT / PDF)
                                   │
                                   ▼
                      Evidence (高保真证据链与定位符)
                                   │
                                   ▼
                      Knowledge (乐享六维知识结构)
                                   │
                                   ▼
                      Project (项目目标、行动与记忆)
                                   │
                                   ▼
                      Feedback (实践反馈与版本迭代)
                                   │
                                   ▼
                      知识健康诊断与演进建议
                                   │
                                   ▼
             Candidate  ──[人工审核]──>  Review  ────>  Committer
                                                          │
                                                          ▼
                                                     Formal State
                                                (formal_state_bypass=0)
```

1. **Knowledge Health（知识健康度评估）**：
   - 算法综合评估「新鲜度（根据修改时间折旧）」、「连接度（通过关联外键识别孤立知识）」、「维护急迫度」与「可操作性」；
   - 自动生成针对具体知识条目的优化建议（如“条目缺乏关联项目，建议归入具体业务线”）；
2. **Knowledge Evolution Timeline（演进时间线）**：
   - 完整追溯知识的前世今生：记录修改内容、演进原因（Why）、来源证据文档（Where）与审核人（Who）；
3. **Context Graph（全要素上下文拓扑图谱）**：
   - 自动生成实体关联网络：
     $$\text{项目 (Project)} \longleftrightarrow \text{知识 (Knowledge)} \longleftrightarrow \text{证据文件 (File)} \longleftrightarrow \text{任务待办 (Todo)} \longleftrightarrow \text{决策依据 (Decision)}$$
4. **Project Memory（项目长期数字记忆）**：
   - 自动沉淀项目的核心四问：**为什么启动**（立项背景）、**做过什么**（里程碑轨迹）、**哪些方法有效**（最佳实践）与**哪些经验可复用**（沉淀资产）；
5. **腾讯乐享知识体系深度融合**：
   - 知识分类完全映射企业级六维标准：`方法论 (Methodology)`、`SOP (操作规范)`、`案例 (Case)`、`决策依据 (Decision)`、`数据规律 (Data Pattern)` 与 `项目经验 (Experience)`；
6. **故障强隔离性（Fault Isolation）**：
   - 演进引擎为只读投影计算，当人为在演进计算中注入异常崩溃时，主工作台的日常浏览、待办创建与审核流 100% 保持正常运行。

### 9.12 同源多版本归并与时态权威治理（A33）
- 针对用户办公中常见的多版本文件（如《年度运营战略方案V1.docx》、《年度运营战略方案V2.docx》、《年度运营战略方案最终版.docx》），系统自动计算文档名称规范化骨架，将其精准归并至同一个逻辑文档 ID（`logical_document_id`）；

- **即时生效无需重启**：用户在控制中心「设置」或主界面随时切换调度频率，底层 `PawScheduler.set_schedule_mode` 立即重新计算并更新下一次巡航倒计时与休眠步长，用户无感。

### 9.14 AI 助手原生联网检索与来源分离（§3.4 第 7 条）
- **默认开启但依赖模型支持**：不单独挂载第三方不可控外部搜索工具，完全取决于用户所选模型本身的原生能力（如通义千问 DashScope 的 `enable_search: true`、DeepSeek/兼容网关自带联网参数）；
- **来源显式分离**：当模型响应包含网络检索信息时，助手界面以专属高亮警示框**明确标注「以下内容来自网络搜索，非工作台依据」**，在视觉和逻辑上与工作台证据脚注（Evidence Footnote）严格区分；
- **零污染原则**：联网检索内容**绝对不计入**工作台 Evidence 资产体系，不得作为正式知识依据，不得被审核链采信；
- **诚实不伪造**：若选定模型（如标准 OpenAI 基础接口或离线规则推理）不支持联网，设置页如实标明「该模型不支持联网」，坚决不弄虚作假。

### 9.15 纯问答定位与坚决不转提案（§3.4 第 4 条）
- **明确决策关闭转提案**：AI 助手定位于**纯严肃问答**，彻底去除“转为待审核提案”入口，坚决杜绝会话旁路污染 Candidate 管道；

### 9.16 每日模型调用上限默认配置（R1 第 2 条 / 第五部分）

- **保留灵活配置**：设置项完整保留于「⚙️ 系统与模型」面板中（可填入任意正整数如 50、100 作为保护上限，填 0 即为无上限）；用户如有个人预算控制需求可随时自主配置开启；
