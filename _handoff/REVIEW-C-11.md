# 第二次修订（2026-10-17，审核 PR #12 返工）

## 发现：扫描导入的文件从不进入【资料】页（2.3.9 起就存在）
- `backend/runtime_core/scanner.py` 的 `_register_source_identity_and_version()` 只写 `logical_document` 和 `source_version_governance`。
- 【资料】页读取的是 `wiki_page` 资料库（`GET /v1/web/workspace/sources`）。这个库只由 `POST /sources/register` 写入，而这个接口只供外部同步调用（WPS 镜像、office_sync）。**本地扫描从来不写它**，所以评委扫描完文件夹后，【资料】页是空的。使用说明里"原始资料一直留在【资料】里可查"目前不成立。
- PR #12 返工版的 PM-S1-01 没有扫描，而是直接调用 `/sources/register` 把文件塞进资料库，绕过了这个缺陷。**不予接受。**

## 修订（新 blob b17402e…，已推送到 codex/C-11）
- PM-S1-01：必须走"放进监控文件夹 → 扫描"的正常流程，不得直接调用资料登记接口；【资料】页要列出该文件并显示完整文件名，按完整文件名搜索能看到它，资料接口也要返回它。
- 恢复负对照 NC-PM-S1：在 2.3.9 上跑 PM-S1-01，必须在 `scanned_file_listed_in_sources` 这项检查失败（2.3.9 确实不列出扫描的文件）。PM-S1-01 中必须有一项同名检查，并且放在任何可能抛异常的步骤之前。

## 产品修复要求（Codex）
- 扫描登记资料时，同时通过 `repository.register_source(...)` 写入资料库：标题用完整文件名（含扩展名），`canonical_location` 用文件路径，`source_origin` 用一个表示本地扫描的新取值（例如 `local_scan`），`content_hash` 用文件哈希，`source_kind` 按扩展名映射（docx/xlsx/pptx/pdf/md）。
- 同一路径的文件更新时，更新已有记录，不新增重复记录（register_source 已按 origin + 路径生成稳定 id）。
- 不影响已有的 B 系列和 PM 系列用例；资料库新增本地扫描的取值时，只增加、不删改（如果有取值限制，就用迁移补充）。
- 单元测试：扫描登记后资料库中有对应记录，标题含扩展名；重复扫描不产生重复记录。
