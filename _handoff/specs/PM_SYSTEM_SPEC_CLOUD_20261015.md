# PAW 项目管理体系升级（云端版原始需求，2026-10-15 产品负责人提供）

> 来源：产品负责人给云端 PAW 执行者的需求文档，原文保存于此，供本地版参考。
> 已删除的内容：第 1 节"访问方式"（服务器地址、SSH 方式），以及云端专属的运维红线。本地版不得连接任何服务器。
> 本地版怎么改编，见 `_handoff/CODEX_START_HERE.md` 第 4 节。两者冲突时，以 CODEX_START_HERE.md 为准。

## 4. 目标（验收的总标准）
用户只看 PAW 工作台，就能掌握每个项目的当前进度、缺口、下一步、风险；用户记录的东西会自动进入对应项目；系统能持续完成"执行 → 补充 → 进化 → 提意见 → 给分析"的循环，并且每个动作在工作台上都有看得见的产出。

### 4.1 首页"今日驾驶舱"
- 需要你决定：所有待用户决定的事项汇总在这里（版本冲突、归属确认、需用户决定的语义结论、无法自动写入的候选等），按影响排序。每条写清"要决定什么 / 选是会怎样 / 选否会怎样"，支持批量处理
- 项目总览：每个项目一行，包含状态、进度、本周变化、最大风险或缺口
- AI 建议：本周最值得做的几件事，每条附依据
- 系统状态：各工作流（巡航、写回、WPS 镜像、备份）红/绿灯，以及最后成功时间

### 4.2 项目页"活的项目档案"
栏目由配置文件定义（不得写死在代码中），默认栏目：
一句话现状 / 目标与指标（当前值、目标值、趋势）/ 进度与里程碑 / 缺口（缺资料、缺数据、缺决定）/ 下一步（AI 建议 + 用户确认的待办）/ 风险与冲突 / 最近变化 / 来源
规则：每个栏目只有一个"当前结论"，旧结论进入历史；每条结论都附 source_version_id，可以点开看原文；每条变更可一键撤销。

### 4.3 输入零门槛
随手记、上传的文件、WPS 镜像来的文件，都自动进入项目：
- 高置信度归属：自动归入，并更新对应栏目
- 低置信度归属：生成"确认归属"卡片，放进"需要你决定"，不得猜测（用户规则：归属问题由用户批准，AI 不得擅自校正）
- 每条输入都生成去向回执，例如"已归入 X 项目 → 更新了'进度'和'下一步'"，用户可在工作台查看

### 4.4 用户已定的常设规则（按此实现，并在系统中记录规则来源为"用户 2026-10-15 设定"）
R1 同一文档族中，较新的资料视为对旧资料的更新：按"文件内写明的生效日期 > 版本号 > 上传时间"确定当前版本，旧版标为 superseded（保留可查，可撤销）
R2 新文件能否归入已有文档族、能否归入某项目，拿不准时一律交给用户决定
R3 栏目更新的风险分级：
   - 一致、补充 → 自动写入（经 Committer，可撤销）
   - 替换（来自同族更新版本）→ 自动写入，旧结论进入历史
   - 冲突（同样有效的资料互相矛盾）→ 进入冲突清单，由用户裁决；裁决前，Agy 回答涉及该处时必须说明存在冲突
   - 新项目、KPI 定义或目标、政策、绩效规则、人员选择、赛制 → 一律由用户决定
R4 用户审核通过的内容必须真正写入系统（不得退化）
R5 巡航每轮处理 5–10 条，一条一条连续处理

## 5. 云端已查明的根因（本地版代码同源，请逐条核实本地是否也存在）
C1 版本裁定只接受用户显式指令：parse_capture_version_directive() 把文件名、标签中的版本信息判为 USER_DECISION_REQUIRED，文档族长期处于未裁定状态，新旧版本同时参与综合 → 项目内容在新旧信息之间摇摆
C2 "新版本 → 项目重新综合"的链路疑似从未触发
C3 巡航规则禁止重读历史 Source，资料入库时只提取一次，漏读的内容永远漏掉
C4 项目上下文没有总量上限（云端某项目曾达 4,450,519 字节），新旧内容不断叠加
C5 Agy 遇到"如何优化"类问题时，回答核验因建议内容无法逐句引用而拒答（ANSWER_NOT_VERIFIED）
C6 系统里没有生成缺口、风险、下一步和周报的环节
C7 待用户决定的事项分散在多处
已有但未串联的模块（优先复用）：paw_project_semantic_coherence.py、identify_stale_outcome_refs()、paw_temporal_authority.py、paw_patrol_project_revision.py、paw_project_outcome.py、paw_project_handbook.py

## 6. 可移植性要求
- 项目档案、栏目配置、版本裁定、冲突判定、健康检查、缺口/风险计算等核心逻辑，放在独立模块中（例如 runtime/paw_project_dossier/），只依赖标准库和现有数据接口；通过"存储适配层"访问数据库
- 语义工作通过工具契约完成（写清输入输出 schema）
- 云端每个阶段结束时会更新 PORTING_NOTES.md

## 7. 阶段（云端原版；本地版的取舍见 CODEX_START_HERE.md）
- A 运维底座：磁盘、备份恢复演练、日志、系统状态红绿灯、手机推送、内存
- B 项目档案数据层：B1 栏目配置 + 档案结构；B2 按 R1/R2 自动裁定文档族版本；B3 逐栏目判定"一致 / 补充 / 替换 / 冲突"，所有写入经 Committer；B4 资料覆盖率与定向复读；B5 项目上下文总量预算；B6 栏目样例交用户确认
  - 验收：不再引用 superseded 版本；新旧资料能正确替换，冲突能进入清单，撤销能恢复原状；抽查 10 份资料（docx/xlsx/pptx/pdf）给出覆盖率
- C 工作台展示：驾驶舱、项目页（来源可点开、历史可查、可撤销）、统一的"需要你决定"收件箱、"最近变化"时间线
- D 输入自动流转：自动归属 + 去向回执；低置信度的进入"需要你决定"
- E 提意见与自我检查：缺口 / 风险 / 下一步（建议与事实分开存、分开显示）；Agy 建议类问答（事实句必须有引用，建议放在标注好的段落中，单句不合格就删掉该句，不整条拒答）；每日健康检查；知识缺口清单
- F 分析与进化指标：周报、跨项目对比、进化指标趋势、20–30 道标准考题回归（答对率下降则不允许发布）

## 11. 前端设计规范
### 11.1 设计语言：与现有工作台保持一致，采用 Claude 风格
1. 先只读阅读现有前端（样式文件、CSS 变量），提取背景色、文字色、强调色、边框、圆角、字体、间距，写入 DESIGN_TOKENS.md。新页面必须复用这些设计变量。
2. 暖米白纸张感背景；强调色为现有的陶土 / 橙棕色，只用于重点；标题用衬线体（Noto Serif SC 一类），正文用无衬线体；大量留白、1px 细边框、柔和圆角、极少阴影；禁止渐变、毛玻璃、霓虹色、密集表格；状态不能只靠颜色区分（例如"● 进行中""▲ 风险"）。
3. 字体和图表库全部打包到本地，不依赖外部 CDN；第三方库须记录许可证。

### 11.2 手绘风格甘特图
用 rough.js（或同类开源库）绘制线条，文字用正常字体，批注可用开源手写体（例如霞鹜文楷），正文不用手写体。
1. 首页"项目总览"甘特图：每行一个项目，横轴为周（过去 4 周到未来 8 周，可切换为按月）；手绘线框条表示周期，斜线填充表示完成比例；一条强调色的手绘虚线标出"今天"；事件图标：◆ 新资料、⚠ 冲突待裁决、✋ 需要你决定、✓ 里程碑完成；点击图标或行可跳转到对应内容。
2. 项目页甘特图：计划条（线框）和实际条（填充），延期部分用强调色斜线；**里程碑缺少日期时不得编造**，画成虚线框并标注"日期待补"，同时计入"缺口"栏目；下方附与时间轴对齐的"最近变化"时间线。
3. 悬停或点击显示详情卡片；固定随机种子，避免刷新时线条跳动。
4. 宽度 ≤ 640px 时改为竖向时间线，不出现整页横向滚动。
5. 数据为空时显示简洁的说明，不显示空白图表。

### 11.3 其他页面元素
"需要你决定"卡片用陶土色左边线；栏目是纸面卡片，"AI 建议"与"事实"在视觉上明确区分；冲突内容左右并排对照，各自附来源；系统状态用小圆点加文字。
