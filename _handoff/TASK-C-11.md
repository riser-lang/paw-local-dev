## 背景
云端版排查发现，搜索词带 `.docx` 一类后缀时，全文检索会报语法错误（云端阶段 B7a）。审核人核对过，本地版代码同源，也有同样的问题：

- `backend/runtime/core/paw_retrieval_core.py` 的 `_recall()`（约第 312 行）把用户输入原样交给 SQLite FTS5 的 `MATCH ?`。输入里只要有 `.`、`"`、`(`、`*`、`:`、`-` 等字符，就会抛出 `sqlite3.OperationalError`。异常被吞掉后，只有中文字数小于 3 的短词才会走 LIKE 兜底，所以"星火导师计划_方案_v2.docx"这类完整文件名**什么都搜不到**。

## 要做的事
1. 用 `git mv` 激活 `tests/pending/required_cases_C-11.json`，内容不改（PM-S1-01 至 03，以及负对照 NC-PM-S1：2.3.9 上必须在 `full_filename_search_found` 这项检查失败）。
2. 修 `_recall()`：
   - 把用户输入安全地转成 FTS5 查询：拆成词元，每个词元加双引号作为短语，内部的双引号写成两个；
   - FTS 出错或没有结果时，任何长度的查询都走有上限的 LIKE 兜底（同时匹配标题和正文），不再只限于短中文词；
   - 不得吞掉异常而不留痕迹：记录一条不含用户原文的诊断日志。
3. 单元测试（ubuntu）：用内存 SQLite 建 FTS5 表，覆盖带点号的文件名、引号、括号、星号、冒号、连字符、纯英文、2 字和 6 字中文；每种情况都不报错，并能找到预期的文档。
4. 检查其他直接把用户输入交给 `MATCH` 的地方（`git grep -n "MATCH"`），同样处理，在 DONE 中列出。
